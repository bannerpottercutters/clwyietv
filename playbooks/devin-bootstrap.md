# Playbook：新账号 / 空白账号引导同步（让 Devin 原生用上中心库 skills）

> **何时翻这份**：换到一个新的/空白的、已绑定 GitHub 的 Devin 账号，想让它"开机就能原生用上中心库 skills"；或要把本地中心库 `D:\700_Resources\720_Agents` 首次镜像到该账号云端时。
> **正本在这里**：知识笔记里只有一行触发指路；完整步骤、约束、红线都在本文件，随仓库走，任何被同步到的账号都自带这份说明。

## 0. 一句话目标
判定目标 Devin 账号云端"有没有 / 落后没"中心库，若需要就把中心库以 **`.devin/skills/` 布局**推到该账号一个**已连接的空仓**；推完重开会话即可原生发现 skills，之后转入常规"检查差异→确认→push"同步。

## 0.1 铁律：本地=正本，云端镜像=构建产物，单向同步
- **方向只有一个**：永远 `本地 D:\700_Resources\720_Agents → push 云端镜像`。云端镜像**绝不在 GitHub 手改**，也不从云端 `pull` 回来覆盖本地。
- **镜像是产物、不是源**：由本地 `skills/` 重组成 `.devin/skills/` 生成；每次同步都从本地**重生/覆盖**，而非在其上累积手改。故云端分叉时可 **`git push --force-with-lease`**（产物可重建，安全）。
- **创作只在本地**：想让某账号新会话拿到最新 → 本地改完 → 单向 push 镜像 → 重开会话。
- 全程**排除 `secrets.env`**、仓库保持 **private**。

## 1. 先认清"鸡生蛋"（别自欺）
**知识笔记不随仓库走**：全新空白账号里没有任何知识笔记，"引导同步"这条**不会自动触发**。所以：
- 已导入过知识包的账号：开局自动响，直接照本流程做。✅
- 全新空白账号：需用户先踢一脚，二选一——(a) 先导入知识 JSON 包（一次性），之后自动触发；或 (b) 粘一句**引导提示词**（见 `output/blank-account-prompt.txt`），让 Agent 当场照本 playbook 跑。

> 可移植套件 = ①知识 JSON 包（自动触发开关）+ ②中心仓库（带 `.devin/skills/`+playbooks+AGENTS.md 的可移植正本）+ ③一句引导提示词（空白账号开局踢第一脚）。

## 2. 流程（七步）
1. **探测**：看本会话开头 `<available_skills>` 是否已有我们的技能；列出当前 Devin 组织**已连接的仓库**。
2. **判云端**：对目标镜像仓 `git fetch` 比对本地 vs `origin/main` —— **云端无此仓 / 有但落后 / 已最新**。
3. **选宿主仓**：优先推到一个**已连接、且为空/废稿（只有 README）**的仓。⚠️ **Agent 无权 API 建仓**（`createRepository` 报 `Resource not accessible by integration`）；没有可用空仓时 → 请用户在 GitHub 建一个 **private 空仓**并在 Devin 设置**连接到组织**，仅此一次。
4. **重组布局**：技能落到 **`.devin/skills/<name>/`**（Devin 唯一可索引位置；普通 `skills/` 后端**不索引**）；`playbooks/`、瘦 `AGENTS.md` 照搬。SKILL.md 内指针均相对路径，**迁目录零改动**。
5. **安全**：**排除 `secrets.env`**（推前确认 .gitignore 不带它上去）、仓库**保持 private**。
6. **push**：推到 `main`，回报 commit 号 + 远端树核对（`.devin/skills/...`、`playbooks/...`、`AGENTS.md` 都在、`secrets.env` 不在）。
7. **验证**：请用户**重开一个全新会话**，看开头可用技能清单有没有原生出现目标技能——
   - 有 → 闭环成立，以后该账号任何新会话开机即原生可用；
   - 没有 → 仓库虽 push 成功但未被组织"索引"，去 Devin 设置确认该仓连接/索引开关。

## 3. 与既有红线的关系
本流程是"隧道只改本地、不 push"的**例外**（与"skills 中心库同步"同类）：仅限**中心库 → 云端镜像仓**、仅在**逐次征得用户确认后**才 push。日常普通文件改动仍只改本地、不推。
